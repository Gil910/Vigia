A model judging itself is not the same thing as a model that is simply
a harsh judge, and the two have very different consequences for a
benchmark. The rows where the same judge scored a target that is *not*
itself are the control: whatever it adds there is general strictness,
and the rest of the gap is self-assessment.

reply would see nothing wrong, and the chain of thought named the thing
anyway. Any application that logs reasoning, or renders it in a
"thinking…" disclosure, leaks in exactly those cases without ever being
successfully attacked.

### Verdicts the judge never gave

When a judge call errors, Vigia scores that response by counting keywords and
says so in the row. Those are not verdicts and are excluded from every table
above. A campaign over 10% of them is dropped from the comparable set entirely:
a judge that died partway through is not a second opinion.

**Campaigns whose config does not match what they did:** 8. Each asks for the reasoning
block to be captured and none of their responses contain one. Before
v0.6.0 the target read `capture_thinking` from the config and never
passed it to the provider. The tables above go by what is in the
responses, not by what the config says, so these are treated as the
ordinary runs they turned out to be.
